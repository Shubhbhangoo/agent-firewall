# v2.3 Migration

v2.3 adds no subsystem and no authorization path. Migration is three
renames, one deleted module, and a set of behaviour changes that only ever
turn an allow into a deny.

## Upgrade

```bash
pip install --upgrade agent-firewall-security==2.3.0
```

## Breaking: three renames

Each of these names carried two guarantees, and on one side of each pair the
name implied a cryptographic result that side never produces. A shared name
lets a guarantee travel to where it does not hold, which is why these are
renames rather than aliases.

### `deception.IntegrityReport` → `ClaimIntegrityReport`

```python
# before
from firewall.deception import IntegrityReport

# after
from firewall.deception import ClaimIntegrityReport
```

`firewall.evidence_integrity.IntegrityReport` means "this hash-chained
evidence log verifies against its checkpoints and signers". The deception
one meant "eight subsystems were asked about this agent and mostly agreed".
It checks no hash and verifies no signature. Reading its
`overall_integrity == "high"` as a verification was exactly the mistake the
shared name invited.

`firewall.evidence_integrity.IntegrityReport` keeps its name.

### `security_memory.Checkpoint` → `EvidenceCheckpoint`

```python
# before
from firewall.security_memory import Checkpoint

# after
from firewall.security_memory import EvidenceCheckpoint
```

The recorder's `Checkpoint` signs a commitment to a point in the decision
recorder's event log; this one signs a commitment to a point in an
evidence-graph chain. Different field sets over different chains, so neither
verifier can check the other's — while the name suggested that verifying one
said something about the other.

`firewall.recorder.checkpoint.Checkpoint` keeps its name, because it is the
name the released audit-artifact format uses.

### `AgentSecurityProfile.trust_score` → `finding_score`

```python
# before
from firewall.adversarial import AgentSecurityProfile
profile.trust_score

# after
from firewall.adversarial import AgentSecurityProfile
profile.finding_score
```

This is the dangerous one. `MeshState.trust_score` is **0.0 when identity
could not be verified**, and it is compared against the quarantine
threshold. `AgentSecurityProfile.trust_score` was **1.0 until something was
found against the agent**. The two run in opposite directions for absence of
information, so wiring the profile into the mesh's `trust_provider` would
have delivered an entirely unchecked agent as fully trusted.

`finding_score` is what the field always measured. An agent nothing could be
checked about still scores 1.0 there, while `risk_level` reports `unknown` —
which is the field to read if you want to know whether anything was
established.

`MeshState.trust_score` keeps its name. `MeshState.identity_verified` stays
a plain `bool` rather than gaining a third "not established" value: the mesh
quarantines on anything short of a verified identity, so it has no use for
one. The docstring now says that, instead of leaving it looking like an
oversight next to the profile's `Optional[bool]`.

## Breaking: `firewall.correlation` is deleted

551 lines, zero importers, zero tests. Two of its six detection paths were
structurally dead — the trust-relationship lookup was a bare `pass` inside a
swallowed `try`, and `temporal_trust_coordination` fired for every pair of
agents behind a comment reading `# Simplified check`. A detector that fires
on every pair carries no information.

Coordination detection now lives in `firewall.intel` as a fourth correlator:

```python
# before -- from firewall.correlation import ...
# after
from firewall.intel import IntelligenceEngine

engine = IntelligenceEngine(posture=posture_engine, trust=trust_graph)
report = engine.analyze()          # coordination findings are in report.hypotheses
```

Every finding is built through `_hypothesis()` and so carries an id, clamped
confidence, supporting facts, a rationale and `basis="inferred"`. Four
patterns, each requiring two distinct agents and a concrete shared value:
shared resource, shared credential material, temporal proximity to a
consequential event, and an escalation path spanning agents.

Proximity states that no trust relationship was checked rather than implying
one, and a spanning path states that reachability is not exploitability.
These are hypotheses for a human or a containment operator.
`FirewallSDK.authorize()` reads none of them.

## Behaviour changes that can newly deny

All three are narrowing. If a deployment was relying on any of them, it was
relying on a fail-open. See
[v2.3-security-corrections.md](v2.3-security-corrections.md).

- **A non-finite request value is now `constraint_denied`.** If a caller was
  passing `NaN` or an infinity into a field compared against a numeric
  constraint, that request was previously admitted by every `_max` ceiling
  and every `_min` floor. Check any path that forwards a parsed JSON number
  straight into a request dict; `json.loads` accepts `NaN`, `Infinity` and
  `-Infinity` as bare tokens.
- **`authorize_continuous` returns `security_dependency_unavailable:
  <names>`** when a *configured* continuous-auth dependency raised while the
  decision was taken. Previously only revalidation withheld. If you see this
  reason appear after upgrading, a wired probe is failing — the probe is the
  thing to fix, not the gate. An *unwired* subsystem is unaffected: unwired
  is `UNKNOWN`, which is a caller's choice rather than a failure.
- **`configure_delegation_budget` no longer resets the consumed total.** A
  startup path that re-applies the same limit on every boot was silently
  clearing the ledger, so the budget never bound. After upgrading, that
  deployment will start seeing `delegation_budget_exceeded` — correctly. To
  give a lineage more room, raise the ceiling; the lineage gets the
  difference above what it already spent.

  `DelegationBudgetState.reserve` and the ceiling now raise `ValueError` on a
  non-finite value. `authorize_with_delegation_budget` already returned
  `invalid_budget_amount` for these, so a caller going through the SDK sees
  no change.

## Corrected analytical output

Not authorization paths, but results that fed human and containment
decisions and were wrong or overstated. Re-read anything that stored or
alerted on them.

- `CounterfactualResult` counts only cases the simulator could replay.
  Nothing counted now yields `unknown` rather than `unchanged`, and
  `.complete` states the coverage. Previously every unreplayed case was
  tallied as a denial, which could turn a widening into a report of
  `improved`.
- `PolicyConflict.rules_involved` is a tuple. It was a generator, so
  `to_dict()` consumed it and every reader after the first saw no rules.
- An unparseable policy is reported as `unanalyzable_policy` instead of
  being dropped.
- `IntelligenceReport.gaps` names every configured source that raised, and
  `.complete` distinguishes a blinded engine from a clean one. Previously
  both produced an empty report.
- `verify_policy_safety`'s docstring no longer claims to use the SDK's
  authorization; it calls `Capability2.evaluate` and exercises none of the
  identity, provenance, revocation or budget gates. The empty tuple is not a
  safety proof.
- The immune system's `trust_collapse` rule no longer substitutes `1.0` for
  a missing score. A missing score is neither collapsed nor healthy, so the
  rule does not apply.

## Nothing to change

`FirewallSDK.authorize()`'s signature, reasons and gate order are unchanged.
Capabilities issued under v2.2 verify under v2.3. The eleven invariants are
the same eleven.
