# v1.9 Architecture: the Agent Security Network

## What v1.9 is

v1.9 turns Agent Firewall from a single-session recorder into a
cross-agent **security network**: given verified `.afw` artifacts from
many sessions, it can answer

> What is this agent capable of, what is it actually doing, what could
> happen if it were compromised, and what should happen when its
> behavior becomes dangerous?

The central design decision: **everything derives from verified
evidence, and every fact carries a provenance basis that is never
conflated.**

## Layering

```text
adapters (python/http/mcp/openai/langchain)
        |  protect/observe, always through FirewallSDK
        v
flight recorder (v1.8) -> .afw artifacts
        |  verified at ingest
        v
CorrelationIndex (ingest + verify + bundle)
        |  verified artifacts only
        v
AgentNetworkGraph (merged nodes/edges, evidence refs, basis)
        |  derived queries
        +--> reachable / why_can / who_can_reach / shortest_path / shared_paths
        +--> behavior detections (inferred, explainable)
        +--> attack paths (reachable/policy-permitted/observed/simulated)
        +--> scenario simulator (isolated workspaces, simulated)
        |  responses route back through
        v
ResponseController -> ContainmentController -> SDK revocation/risk
        |  (observe -> warn -> restrict -> quarantine -> contain)
        v
existing authorization pipeline (never bypassed)
```

## Provenance (the core invariant)

Every node and every edge in the network carries one of:

| basis | meaning |
| --- | --- |
| `observed` | recorded directly in an artifact's event chain |
| `derived` | computed deterministically from observed facts (reachability, paths) |
| `inferred` | heuristic conclusion (behavioral detections) |
| `simulated` | produced by the scenario simulator in an isolated workspace |
| `unknown` | evidence missing or unverifiable; never promoted |

Rules that make this real:

1. A failed or unverifiable artifact is **refused at ingest** -- its
   facts never enter the network. (Optional `allow_failed` flags it so
   callers can exclude it; the graph builder still refuses.)
2. `add_inferred` only accepts `inferred`/`simulated` nodes and edges.
   A node cannot claim `observed` provenance after the fact.
3. Attack paths use a status taxonomy (`simulated` < `reachable` <
   `policy-permitted` < `observed`); reachability is never reported as
   exploitability, and a simulated hop is never reported as observed.
4. The simulator runs in throwaway workspaces seeded from recorded
   facts plus the scenario's mutations, and its report is labeled
   `simulated`. Contradictions (e.g. removing a capability the agent
   never held) are reported as `unverifiable`, never papered over.

## The integration layer

One `AgentAdapter` base defines the shared contract: identity (best
effort, `complete: false` when unknown), capabilities (read from the
SDK's own registry), `protect` (wrap a handler so the real
`FirewallSDK` pipeline authorizes every call, via the v0.9
`GenericToolAdapter`), `observe` (record tool results post-hoc into the
flight recorder), and context (correlation ids, parent agents).

Environment adapters (`python`, `http`, `mcp`, `openai`, `langchain`)
are thin translators. They hold no authority of their own, and they
degrade gracefully: an HTTP endpoint with no mapped action refuses with
an explanation instead of guessing; an agent with no identity reports
`complete: false` instead of inventing one. Unknown environments fail
fast at adapter creation.

## Response automation

`ResponseController` maps detections to stages
(`observe -> warn -> restrict -> quarantine -> contain`) through a
declarative `ResponseRule` policy. Discipline:

- policy-driven (an action happens only when the policy says so),
- auditable (every action lands in the flight recorder and the
  control-plane audit),
- explainable (every action carries the detection + reason that
  triggered it),
- fail-closed (a policy-evaluation error never silently downgrades; a
  containment failure raises rather than leaving an agent unrestrained),
- reversible where safe (recovery re-issues equivalent authority),
- human approval for high-impact stages (`quarantine`, `contain`)
  unless the policy explicitly auto-approves.

The controller holds no signing keys and can only do what the
underlying SDK APIs allow. There are no hidden autonomous privileges.

## Security boundary (unchanged from v1.8)

- Recording is observational: it happens after decisions exist and can
  never influence one. No recorder attached means zero overhead.
- The verifier only reads. Failed artifacts never enter the network.
- The replay laboratory and scenario simulator run in isolated
  throwaway workspaces and never touch a live SDK.
- Containment is the only write path, and it is routed through the
  SDK's own revocation registry and risk context -- never around
  `authorize()`.
- Analysis (graph, detections, paths, simulations) is strictly above
  the authorization pipeline. There is no "AI says safe -> allow" path.

## What v1.9 does not claim

- A detection is a heuristic finding (`inferred`), not a fact.
- A reachable path is not an exploited path. "potentially_dangerous"
  is an analytical label over recorded authority.
- A correlation id is a label, not proof of relationship; bundle
  verification statuses are always reported.
- A scenario outcome is `simulated`, never presented as history.
- Integrity does not imply trust: an artifact proves what its
  cryptographic evidence proves, and nothing more.
