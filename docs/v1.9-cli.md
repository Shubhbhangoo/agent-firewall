# v1.9 CLI Reference (network commands)

The v1.9 network commands extend the v1.8 CLI. Every v1.7/v1.8 command
keeps its exact behavior.

## Workflow

```bash
# 1. Create a network state file (a ledger of ingested artifacts)
firewall network init --out network.json

# 2. Verify + ingest artifacts (failed artifacts are refused)
firewall network ingest session-a.afw session-b.afw --state network.json

# 3. Correlate across artifacts (shared correlation/incident ids, agents)
firewall network correlate network.json

# 4. Ask questions
firewall network graph network.json --agent agent-a --reach
firewall network graph network.json --who-can-reach /etc/shadow

# 5. Detect suspicious behavior
firewall detect network.json --min-severity medium

# 6. Discover attack paths
firewall attack-path network.json --summary
firewall attack-path network.json --agent agent-a --to /etc/shadow

# 7. Simulate a scenario (isolated workspace)
firewall network simulate network.json scenario.json

# 8. Apply a graduated response policy
firewall respond network.json --policy policy.json
```

## Exit codes

`0` success / meaningful positive result · `1` meaningful negative
result (no detections, no paths, nothing to correlate) · `2` inputs
could not be used.

## Command reference

### network init

```bash
firewall network init [--out network.json] [--note "..."]
```

Creates an empty network state file. The state holds artifact paths and
verification statuses only -- never artifact content, never secrets.

### network ingest

```bash
firewall network ingest <artifact.afw>... [--state network.json]
    [--out new-state.json] [--allow-failed] [--json]
```

Verifies each artifact with the independent verifier and records it in
the state. A failed or unverifiable artifact is skipped with a warning
(ingested but flagged only with `--allow-failed`; its facts still never
enter the graph).

### network graph

```bash
firewall network graph <state>
    [--agent <agent> --reach]
    [--agent <agent> --why <action>]
    [--who-can-reach <resource>]
    [--shared <resource> --agents a,b]
    [--json]
```

### network correlate

```bash
firewall network correlate <state> [--json]
```

Lists correlation bundles: shared correlation ids, shared incident ids,
shared agents, and redaction provenance.

### network simulate

```bash
firewall network simulate <state> <scenario.json> [--json]
```

See `docs/security-intelligence.md` for the scenario schema and kinds.

### detect

```bash
firewall detect <state> [--min-severity low|medium|high|critical] [--json]
```

### attack-path

```bash
firewall attack-path <state> --summary
firewall attack-path <state> --to <target>
firewall attack-path <state> --agent <agent> --to <target>
```

`--summary` lists sensitive resources recorded in the network.
`--agent --to` gives the shortest path with enabling capabilities and
break-path suggestions.

### respond

```bash
firewall respond <state> [--policy policy.json]
    [--rule <rule-id>] [--min-severity <sev>] [--json]
```

Without `--policy`, sensible defaults apply (repeated denials ->
restrict; credential-shaped access -> quarantine). Responses run in a
fresh in-memory workspace against the current detections; the policy
file schema lives in `docs/security-intelligence.md`.

## Error messages

Errors explain what happened, why it matters, and how to fix it:

```text
error: refusing to ingest artifact sess-x: verification status is failed
error: --agent is required with --why
error: unknown agent environment: 'foo'; known: http, langchain, mcp, openai, python
```
