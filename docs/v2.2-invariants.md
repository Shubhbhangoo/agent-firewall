# v2.2 Machine-Checkable Security Invariants

Eleven properties that must hold of every execution. Each is stated once,
in `firewall/invariants/registry.py`, and checked by exactly one
function — so an invariant with no check is a missing registry entry
rather than a silently absent property.

```python
from firewall.invariants import assert_all, check_all

report = check_all(sdk, policy_history=history)   # returns findings
assert_all(sdk, policy_history=history)           # raises unless all hold
```

```bash
python -m firewall.invariants
```

The suite is not an authorization authority and cannot become one. It
returns `InvariantResult` findings; `FirewallSDK.authorize` remains the
only thing that decides. A `VIOLATED` report revokes nothing and a
`HOLDS` report grants nothing — `AUTHORIZATION_UNIQUENESS`, which this
package ships, is what keeps that true of the package itself.

## Unverifiable is not a pass

Status is three-valued: `HOLDS`, `VIOLATED`, `UNVERIFIABLE`.

`UNVERIFIABLE` means the check ran and could not establish the property —
a source file that would not parse, a subsystem that is not wired, a live
check with no state to inspect. `InvariantReport.holds` is false whenever
any invariant is unverifiable, and `assert_all` raises on it. Accepting
unverifiables would make the assertion satisfiable by breaking the
checker, which is strictly easier than satisfying the invariants.

A checker that raises is converted to `UNVERIFIABLE`, never to `HOLDS`.

## The eleven

### Structural — checked by reading the source tree

**1. AUTHORIZATION_UNIQUENESS.** An authorization verdict is constructed
only inside the authorization boundary. No subsystem — risk, intel, twin,
telemetry, UI, adapter — can produce one.

**2. MODEL_NON_AUTHORITY.** Only the terminal gate may allow. Every other
gate can deny or abstain, so adding a gate — a model verdict, a risk
score, a behavioural signal — can only narrow authority, never widen it.

**3. CONTROL_PLANE_INTEGRITY.** Mutable control-plane state is reachable
only through the SDK's own API. No subsystem holds the live capability,
identity, task or posture container. In v2.2 this is what
`FirewallSDK.known_capabilities()` exists for: it returns a
`MappingProxyType` over the registry the lineage walk resolves through,
so a caller cannot inject a forged parent or delete an inconvenient
ancestor, and it stays a live view so no caller can pin a snapshot past a
revocation.

### Self-contained probes — no live system required

**4. PROVENANCE_INTEGRITY.** There is one provenance vocabulary, and
combining claims never strengthens one: inferred is not observed,
simulated is not observed, and an unrecognized label degrades to unknown.

**5. EVIDENCE_INTEGRITY.** Recorded evidence cannot be altered without
verification failing *and the alteration being named*.

**6. FAIL_CLOSED.** Hostile, malformed and unauthorized requests are
denied with a verdict. The authorization path never raises in place of
deciding. This is the invariant that found `authorize(cap, action="")`
raising out of the first gate instead of returning `invalid_action`.

As shipped in v2.2 the second sentence was broader than the check behind
it. All eight probes were malformed *input* against a healthy SDK, so the
invariant held while five of the boundary's own dependencies could still
turn a decision into an exception. v2.5 attacked that gap, made the
statement true of unavailable state as well, and added nine
dependency-failure probes with per-probe controls — see
[v2.5-boundary.md](v2.5-boundary.md).

### State-dependent — need an SDK that has been used

**7. SIMULATION_ISOLATION.** A simulation leaves production control-plane
state byte-identical and declares its decisions simulated.

**8. DELEGATION_MONOTONICITY.** Every signed delegation edge agrees with
the registered one and narrows: a delegated capability is never broader
than the parent whose fingerprint it carries.

**9. CAPABILITY_MONOTONICITY.** Every registered lineage edge narrows,
including attenuation — which carries no signed parent and so is
invisible to `DELEGATION_MONOTONICITY`. The two are not redundant.

**10. REVOCATION_MONOTONICITY.** Revocation propagates to every
descendant and is never undone: a revoked capability's children are
effectively revoked too.

**11. POLICY_NON_WIDENING.** Every applied policy transformation narrowed
authority or left it unchanged. Unverifiable without a transformation
history: pass `policy_history=[(before, after), ...]`.

## What a source-only run establishes

`python -m firewall.invariants` with no SDK checks six invariants (the
three structural and the three self-contained probes) and reports the
other five as `UNVERIFIABLE`. Exit codes:

| Code | Meaning |
| --- | --- |
| 0 | every invariant that could be checked holds |
| 1 | an invariant is **violated** — a security defect |
| 2 | nothing violated, something unestablished, and `--strict` was given |

Without `--strict` an unverifiable result exits 0 so a source-only CI job
can gate on the structural invariants without failing on every run for
lack of a running system; the output still names what it could not check.
With `--strict` the command is exactly `assert_all`.

The five state-dependent invariants are exercised by
`tests/test_v2_2_invariants.py` against SDKs that have issued, delegated,
attenuated, revoked and simulated. CI runs both: the full suite, then the
source-tree gate.

`--list` prints each invariant's statement and marks the ones that need
live state.
