# Agent Firewall v0.9 Performance Baseline

This document records the local performance baseline measured during v0.9 development.

## Method

Benchmarks are implemented in `test_v09_benchmarks.py` and use `time.perf_counter_ns()` with a warm-up phase before collecting samples.

Run them with:

```bash
pytest test_v09_benchmarks.py -q -s
```

The results below are development-machine measurements. They are intended for regression tracking, not as universal performance guarantees.

## Baseline

| Operation | Average | Median | p95 |
| --- | ---: | ---: | ---: |
| Capability verification | 190.10 µs | 197.40 µs | 234.10 µs |
| SDK authorization | 168.30 µs | 145.90 µs | 267.40 µs |
| ProtectedTool execution | 236.25 µs | 221.95 µs | 381.50 µs |
| Generic adapter execution | 292.40 µs | 205.45 µs | 444.70 µs |
| OpenAI adapter execution | 214.94 µs | 168.65 µs | 356.50 µs |
| Anthropic adapter execution | 216.26 µs | 174.10 µs | 374.10 µs |
| SQLite lifecycle append | 1.95 ms | 1.89 ms | 2.44 ms |
| SQLite lifecycle read | 1.14 ms | 1.12 ms | 1.46 ms |

## Interpretation

The in-memory authorization path is measured in hundreds of microseconds in this baseline. Tool adapters add translation and wrapper overhead while continuing to use the same authorization core.

SQLite operations are materially slower because they include persistent storage work. Their numbers should be compared only against later measurements using the same workload and environment.

## Reproducing and comparing

When comparing future releases:

1. Run the benchmark suite on the same machine where possible.
2. Keep Python and dependency versions fixed.
3. Run the same benchmark command and workload.
4. Compare median and p95 as well as average latency.
5. Treat large changes as investigation signals rather than automatic regressions.

The benchmark suite is deliberately separate from correctness assertions. Full correctness and security validation remains the responsibility of the repository's test suite.
