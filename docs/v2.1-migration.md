# v2.1 Migration Guide (from v2.0)

v2.1 is **backward compatible with v2.0**. All v2.0 APIs, invariants,
state files, and CLI commands keep working unchanged; v2.1 adds new
subsystems *above* the authorization boundary. Existing tests pass
unmodified (the full v2.0 suite is part of the v2.1 CI gate).

## What changed

- Version: `2.0.0` -> `2.1.0` (pyproject.toml).
- New packages: `firewall.defense`, `firewall.a2a`,
  `firewall.attackgraph`, `firewall.twin`, `firewall.evidence_graph`,
  `firewall.capability2`, `firewall.immune`, `firewall.research`,
  `firewall.intel`, and `firewall.benchmarks`.
- New CLI commands: `defense`, `delegate`, `capability`,
  `attack-graph`, `twin`, `evidence`, `immune`, `research`, `recover`.
- The console gained a v2.1 defense panel (live mesh state, a2a trust
  graph, attack graph, twin counterfactuals, evidence graph, immune
  system).
- Two small hardening changes to existing primitives, both fail-closed:
  - `IdentityRegistry` and a2a state loading reject non-object state
    files with a clear error instead of an `AttributeError`.
  - Evidence payloads enforce string length and nesting-depth limits.

## Migration steps

### 1. Nothing to change for v2.0 users

Every v2.0 module, CLI command, state file, and test is unchanged. Run
the v2.0 suite to confirm: `pytest -q`.

### 2. Optional: adopt the v2.1 primitives

New capability starts with the defense mesh:

```python
from firewall.ident import IdentityRegistry
from firewall.defense import DefenseMesh
from firewall.sdk import FirewallSDK

reg = IdentityRegistry(state_path="identities.json")
sdk = FirewallSDK()
mesh = DefenseMesh(reg)
mesh.attach_sdk(sdk)

state = mesh.evaluate("agent-a")   # continuous evaluation
mesh.quarantine("agent-a", actor="soc", reason="incident")
```

### 3. Optional: a2a zero trust

```python
from firewall.a2a import AgentToAgent

a2a = AgentToAgent(reg, state_path="a2a.json")
rel = a2a.establish(
    initiator="alice", responder="bob",
    permissions={"allowed_actions": ["read"]},
    ttl=3600,
)
decision = a2a.authorize(actor="alice", target="bob", action="read")
```

### 4. Optional: evidence graph

```python
from firewall.evidence_graph import EvidenceGraph, KeyEvidenceSigner

graph = EvidenceGraph(signer=KeyEvidenceSigner(), state_path="evidence.json")
graph.append("observed", "agent-a", "decision", {"allowed": True})
graph.append("inference", "agent-a", "behavior", {"score": 0.9})
assert graph.verify()["status"] == "verified"
```

### 5. Optional: immune loop

```python
from firewall.immune import ImmuneSystem, ImmunePolicy, ImmuneRule

immune = ImmuneSystem(mesh, posture=posture, containment=controller,
                      evidence_graph=graph)
immune.set_policy(ImmunePolicy(rules=(
    ImmuneRule("compromised_posture", stage="quarantine",
               min_severity="high"),
)))
result = immune.run_cycle()
```

### 6. Optional: digital twin

```python
from firewall.twin import SecurityTwin
from firewall.network import AgentNetworkGraph

twin = SecurityTwin.from_network(network_graph)
report = twin.compromise("agent-a")     # simulated, isolated
```

## Behavior notes

- **Same-tick re-issuance**: `FirewallSDK.issue()` derives
  `issued_at` from the wall clock, so two issues within the same tick
  produce the identical signed capability and share a fingerprint.
  The mesh re-issues during recovery with its own clock to guarantee a
  fresh fingerprint; if you re-issue capabilities yourself after
  quarantine, advance the clock or pass an explicit `issued_at`.
- **Task activity in a2a**: a relationship can be established while a
  task is inactive; authorization denies until the task is active. This
  avoids a race where establishment depends on task lifecycle.
- **Containment idempotence**: the immune system reports a stage as
  already satisfied when the agent is already in the target containment
  state (e.g. the mesh auto-quarantined it first).

## Rollback

v2.1 ships on its own branch (`v2.1`). To roll back, revert to `v2.0`;
state files produced by v2.1 subsystems (`mesh.json`, `a2a.json`,
`evidence.json`, `attack-graph.json`) are not read by v2.0 and can be
deleted. The core `identities.json` / SDK SQLite stores are shared and
remain compatible.
