# v1.8 Developer Console

The browser console is the visual home of the security recorder. It
shows the same security state as the CLI, derived from the same
modules -- switching interfaces, not switching products.

## Recorder panel

The console now serves a **Security Flight Recorder** panel:

- **Verification banner.** `verified` / `failed` / `unverifiable` /
  `incomplete` / `redacted` -- the five states are rendered distinctly
  and never conflated, with every finding listed.
- **Agent security timeline.** The chronological story: session start,
  capability issued, actions allowed/denied, containment, recovery.
  Every entry shows its severity and links back to its event sequence
  number.
- **Security trajectory.** The posture ladder
  (`trusted -> unusual -> suspicious -> high_risk -> contained ->
  recovered`) with the recorded evidence for every transition.
- **Security relationship graph.** Derived nodes (agents, capabilities,
  issuers, tools, policies, sessions) and edges (issued, delegated,
  attenuated, revoked, allowed, denied, bound_to, belongs_to), plus a
  full node/edge dump. "Why could this agent do this?" and "what could
  it reach?" are one CLI call away:
  `firewall graph session.afw --agent X --why Y`.
- **Containment.** Current states and the audited history.
- **Replay laboratory.** Propose rules (delegation depth, trusted
  issuers) and get the counterfactual comparison: per-decision
  observed vs counterfactual, plus newly denied / newly allowed /
  verified / unverifiable counts.

## Routes

| route | auth | purpose |
| --- | --- | --- |
| `GET /api/recorder` | none | full recorder projection (session, verification, timeline, trajectory, graph, containment, redactions) |
| `POST /api/replay` | none | counterfactual replay (read-only analysis, throwaway workspaces) |
| `POST /api/control/containment` | bearer token | audited containment actions |
| `GET /api/control/state` | bearer token | control-plane state (includes containment + audit) |

## One system, two interfaces

- The CLI and browser call the same `firewall.timeline`,
  `firewall.replaylab`, and `firewall.verify` modules.
- Both use identical terminology (`observed`, `counterfactual`,
  `verified`, `redacted`, posture names).
- Artifacts recorded or exported from either interface open in the
  other.

## Demo mode

Demo mode builds a genuine recorded session through the real SDK:
allow, deny, delegation, containment, recovery. Everything the recorder
panel shows in demo mode is real recorded material, not mock JSON.
