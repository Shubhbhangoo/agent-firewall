# v2.0 Identity, Task, Passport, and Attestation Model

## Identity

An agent identity answers *who*. It is a persistent, cryptographically
bound record:

```text
agent_id, identity_version, owner, environment, created_at,
status (active | revoked | retired), public_key, key_fingerprint,
parent_agent, issuer, metadata
```

Lifecycle:

```bash
firewall identity create agent-a --registry identities.json --passphrase pw
firewall identity show    --registry identities.json --passphrase pw
firewall identity rotate  agent-a --registry identities.json --passphrase pw
firewall identity revoke  agent-a --reason "compromised" --registry ... --passphrase pw
```

Rules:

- **Identity is not authorization.** An active identity proves who an
  agent claims to be (subject to issuer trust). Whether it may do
  anything is decided by the authorization pipeline alone.
- **Verification is honest.** `verify()` checks the signature over the
  canonical identity payload with the recorded public key and the
  status. Forged, stolen, rotated-out, revoked, retired, and unknown
  identities all fail.
- **Rotation is versioned.** `rotate` replaces the key and bumps
  `identity_version`; old signatures stop verifying.
- **Parent/child** is recorded provenance, not authority: it says who
  issued the identity, it grants nothing.
- **Persistence is atomic.** With a passphrase the private key is
  stored encrypted (PBKDF2 + AES-GCM); without one it is in-memory only.
  Private keys never enter passports, attestations, or artifacts.

## Task-bound authority

A task scopes authorization: the agent acts *for a task* that carries
its own permissions, lifecycle, and delegation chain.

```python
root = tasks.create(
    agent_id="agent-a",
    permissions={"allowed_actions": ["read", "write"], "amount_max": 100},
)
child = tasks.delegate(root, agent_id="agent-b",
                       permissions={"allowed_actions": ["read"]})
```

Guarantees:

- **Delegation only narrows.** The child's effective permissions are
  the intersection of the parent's and the grant. A chain
  (A -> B -> C) can never confer more than the legitimate chain grants.
- **Subtree revocation.** Revoking a root task revokes the whole chain.
- **Expiration** is enforced at check time (`is_active`).
- **Fail closed.** A lineage cycle raises; a missing ancestor raises;
  a completed/revoked/expired task grants nothing.

```bash
firewall task create agent-a --registry identities.json --permissions '{"allowed_actions": ["read"]}'
firewall task delegate <task-id> agent-b --registry identities.json --permissions '{"allowed_actions": ["read"]}'
firewall task show --registry identities.json
```

## Security passport

A passport is a deterministic, versioned, signed summary:

```text
identity | posture | tasks | capabilities | delegated authority |
provenance | reach | incidents | containment | signature | key fingerprint
```

```bash
firewall passport show agent-a --registry identities.json --out passport.json
firewall passport verify passport.json --registry identities.json
```

Verification distinguishes `verified` / `failed` / `unverifiable`.
Passports never contain private keys; a passport whose identity is
revoked, retired, unknown, or whose signature does not verify against
the recorded key is never accepted.

## Cryptographic attestation

Signed, versioned statements about security-relevant facts, issued
under an agent identity key:

```python
authority.issue(
    agent_id="agent-a",
    subject="task:123",
    statement_type="authority",
    payload={"task_id": "task-123"},
)
```

- Every attestation records `alg` (currently `Ed25519`) and
  `key_fingerprint`, so future algorithms (e.g. post-quantum) can be
  introduced without changing the model.
- The verifier returns `verified` / `failed` / `unverifiable` and never
  conflates them: unsupported algorithms and unknown identities are
  `unverifiable`, revoked identities and bad signatures are `failed`.

```bash
firewall attestation verify attestation.json --registry identities.json
```
