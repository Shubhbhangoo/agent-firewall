# v2.7 performance: what keeping authority attached to the act costs

Methodology follows the suite's standard (see `firewall/benchmarks.py`):
warmup, then `repeats` timed calls reported as median and p95 of
`time.perf_counter`; `operations_per_second` derives from the median. All
figures below are from one development machine (CPython 3.10, Windows 10)
and are directional, not a benchmark. Run `python -m firewall.benchmarks
execution` locally for current numbers.

## What is measured

The four required layers are measured as the **same boundary with one more
protection attached**, never against an intentionally weaker path:

| benchmark | layer | what one operation does |
| --- | --- | --- |
| `execution_authorize_only` | authorize | `FirewallSDK.authorize()` - the v2.6 reference |
| `execution_issue` | authorize + lease | `authorize_execution()`: authorize, outer epoch window, request digest, chain fingerprints, policy version, one lease-store write |
| `execution_validate` | + validation | the deny-only continuity re-establishment over one live lease, isolated |
| `execution_reserve` | + reservation | `authorize_execution` + `reserve_execution` with a fresh execution identity: validation and the atomic CAS |
| `execution_denied` | + revocation | fresh grant, authorize, revoke, then reserve: the fail-closed refusal path |

Because each number shares its estate shape with the others, the delta
between adjacent rows is the honest price of that protection layer. The
denied row is included so the cost of fail-closed is published rather than
asserted away.

## Results (directional)

| layer | median ops/s (higher is better) |
| --- | --- |
| authorize only | ~3,800 |
| authorize + lease issue | ~2,100-3,000 |
| + continuity validation (per check) | ~4,300 validations/s over one lease |
| + reservation (full issue + reserve) | ~1,500 |
| fail-closed refusal (fresh grant, revoke, reserve) | ~1,200 |

Readings from the run that produced this doc:

- `execution_authorize_only`: 100 ops, median 26 ms (~3.8k ops/s).
- `execution_issue`: 50 ops, median 18-24 ms (~2.1-2.8k ops/s).
- `execution_validate`: 100 validations, median ~22 ms (~4.3k ops/s).
- `execution_reserve`: 50 full issue+reserve cycles, median ~33 ms (~1.5k ops/s).
- `execution_denied`: 20 deny cycles, median ~17 ms (~1.2k ops/s).

## Reading the numbers

- The lease adds on the order of a fraction of an authorization's cost, not
  a multiple. `execution_reserve` is authorize + lease + validation +
  reservation and lands in the same order of magnitude as `authorize`
  alone, which is the claim that matters: the continuity machinery is
  dominated by the signature verification the boundary already performs,
  and the extra reads are a small set of in-memory lookups plus one epoch
  comparison.
- The isolated validation number (~4.3k/s) is below the raw gate count of
  an `authorize` because it re-runs the cryptographic verification of the
  presented capability, which `authorize` also runs; it is not an added
  verification layer on top of an already-verified object. The honest
  framing: each progression re-establishes the basis the way the boundary
  itself would, so an execution under a lease costs about what the original
  authorization cost, paid at each recorded step instead of once.
- The denial path is *slower* than the allow path here, unlike the adaptive
  denial in v2.4. The reason is honest: each denied operation builds a
  fresh grant and revokes it, because revocation is permanent and the
  benchmark refuses to measure the already-terminal fast path. Publishing
  the slow, real number is the point.
- Spread (p95 vs median) on this machine is large for the small counts the
  suite uses to stay CI-fast; treat the medians as order-of-magnitude.

## What is not claimed

No comparison is made against an execution path with the validation
disabled, because no such path exists or should exist. The cost of v2.7 is
the cost of the lease, the CAS, and the per-progression re-validation, and
that is what is reported. These numbers do not justify skipping a check;
the security property is the reason the checks exist.
