# v2.1 Performance Benchmarks

`firewall.benchmarks` measures the critical paths of the Autonomous
Agent Defense Layer. Run everything:

```bash
python -m firewall.benchmarks
# or select:
python -m firewall.benchmarks evidence_append twin
```

## Benchmarks

| name | measures | default size |
| --- | --- | --- |
| `evidence_append` | signed event append throughput | 200 events |
| `evidence_verify` | full-chain verify throughput | 200 events |
| `attack_graph` | network -> attack graph build + path query | 60 agents x 3 caps |
| `twin` | one compromise counterfactual | 40 agents |
| `mesh` | evaluate a full agent population | 100 agents |
| `a2a_chain` | authorize through a delegation chain | depth 30 |
| `capability2` | policy evaluation throughput | 1000 evals |

The suite is deliberately conservative: small enough to run in CI
seconds, large enough to expose O(n^2) behavior.

## Bottlenecks and notes

- **Evidence verify is the slowest path per event** (Ed25519
  verification per event). For very large graphs, batch verification or
  checkpointed verification is the natural optimization.
- **A2A authorize with long chains** walks the lineage per call
  (O(depth) with lineage resolution per relationship). Fine for depth
  <= 100; for pathological depth, cache effective permissions per
  relationship until a mutation.
- **Attack graph BFS** expands each node at most once, so it is bounded
  by nodes x edges and terminates on cyclic graphs.
- **Twin counterfactuals** clone the graph per query (O(nodes + edges));
  reuse the baseline snapshot when running many counterfactuals against
  the same environment.

## CI gate

`test_v2_1_benchmarks_ui_secrets.py::TestBenchmarks` asserts every
benchmark completes without error and returns a report. It does not
assert absolute timings (they are machine-dependent); regression is
tracked by watching `events_per_second` / `seconds` over time.
