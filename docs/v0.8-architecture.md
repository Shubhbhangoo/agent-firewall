# Agent Firewall v0.8 Architecture

## Overview

v0.8 keeps authorization decisions and security state separated into focused layers while exposing lifecycle history through the SDK.

```text
                  FirewallSDK
                       │
          ┌────────────┼────────────┐
          │            │            │
     Capability    Revocation   Lifecycle
       logic         state        recorder
          │            │            │
          │       SQLite store  SQLite store
          │
          └──── authorization ────┘
                       │
                 decision/evidence
```

## Capability layer

Capabilities are signed permissions. The SDK issues, verifies, attenuates, delegates, serializes, transports, and authorizes capabilities.

The capability fingerprint is the stable identity used to associate lifecycle and revocation state with a specific capability.

## Lifecycle layer

`LifecycleRecorder` creates structured `LifecycleEvent` records. The supported event types are:

- `ISSUED`
- `DELEGATED`
- `ATTENUATED`
- `USED`
- `REPLAYED`
- `REVOKED`
- `DENIED`
- `EXPIRED`

Lifecycle events retain capability identity and relevant decision metadata. Request details are copied before recording so later caller mutation cannot rewrite historical evidence.

## Persistence layer

`SQLiteLifecycleStore` provides append-oriented durable storage for lifecycle events. A recorder can load existing events when initialized with a persistent store, allowing lifecycle history to survive process or SDK restart.

Revocation persistence is maintained separately through the revocation store. The SDK can configure both stores independently:

```python
sdk = FirewallSDK(
    revocation_store_path="revocations.db",
    lifecycle_store_path="lifecycle.db",
)
```

## Authorization lifecycle

A successful request produces `USED`. A denied request produces `DENIED`. Expiration produces `EXPIRED`. Replay detection produces `REPLAYED`, and revocation produces `REVOKED` when the capability is revoked. These records are distinct so consumers can reconstruct what happened instead of treating every failed request as the same state.

## Restart model

On shutdown, the SDK closes its persistent stores. On startup, the lifecycle recorder restores the existing lifecycle history from SQLite and the revocation registry restores persistent revocation state.

Cross-layer tests verify that a revoked capability remains revoked after restart and that its lifecycle history remains available.

## Concurrency

The v0.8 test suite exercises concurrent lifecycle writes and concurrent revocation attempts. The persistence layer is expected to preserve individual events without cross-capability leakage or silent loss.

## Public API

The package root exports the primary v0.8 primitives through `firewall.__init__`, including `FirewallSDK`, lifecycle types, lifecycle recorder, lifecycle store, and revocation types.
