# v2.1 Threat Model

v2.1 assumes the v2.0 threat model (identity forgery, capability theft,
delegation escalation, provenance poisoning, confused-deputy, supply-chain
compromise) and adds the threats that an **autonomous agent ecosystem**
introduces: agents that act without human supervision, agents that
communicate with each other, models whose output is plausible but wrong,
and an attack surface that is evaluated and changed continuously.

## Trust assumptions

1. The v2.0 authorization pipeline (`FirewallSDK.authorize()` and its
   gates) is trusted and remains the **only** decision authority. Nothing
   in v2.1 can allow, deny, or relax a decision it makes.
2. Identity issuers and their signing keys are trusted. A fully
   compromised issuer is out of scope (same as v2.0).
3. The evidence graph's signers are trusted to sign what they observe.
4. The operator/approver is trusted to make the final call on
   high-impact defensive actions.
5. Model output (LLM reasoning) is **never** trusted to authorize
   anything. It is advisory by construction and flagged as such.

## Adversaries

| adversary | capability | defended by |
| --- | --- | --- |
| Malicious agent | presents capabilities/identities it does not hold | defense mesh fail-closed evaluation; capability provider binds capability to agent; identity verification |
| Forged identity | fabricates an identity record | `IdentityRegistry.verify` (signature + status + fingerprint); mesh rejects unknown/revoked |
| Delegation abuser | tries to widen authority through A -> B -> C chains | task intersection, a2a `effective_permissions` intersection, capability2 `is_narrower_than`, v1.x `_constraints_are_narrower`; widening raises at delegation time |
| Replayer | replays a signed request/nonce | `ReplayProtector.consume_nonce` (once-only); a2a challenge nonces are single-use and TTL-bound |
| Tamperer | edits, reorders, or deletes evidence | evidence graph hash chain + signatures; every violation reported (`failed`/`unverifiable`) |
| Confused deputy | causes a privileged agent to act on attacker-chosen input | a2a scoped relationships + SDK provider gate; capability2 resource/scope constraints; tool output never carries authority (v1.x) |
| Model manipulator | prompts the reasoner to recommend malicious actions | immune policy rules are deterministic; model output can only *recommend*, never execute |
| Trust manipulator | establishes/revokes trust to gain reach | a2a mutual authentication (challenge/signature), scoped grants, recursive revocation, teardown |
| Poisoner | feeds false "observed" evidence | evidence kinds are structural; promotion to `observed` is explicit, signed, and referenced (`promoted_from`) |
| Resource explorer | probes what a compromised agent could reach | twin counterfactuals label everything `simulated`; reachability is never exploitability |

## Attack scenarios and the invariant each one violates if it succeeds

| scenario | violated invariant if it succeeds |
| --- | --- |
| `malicious_agent` | credentials/capabilities do not become authority by presentation |
| `forged_identity` | identity does not equal authority; verification is honest |
| `delegation_chain` | delegation can only narrow |
| `capability_escalation` | a delegated capability never gains authority |
| `revocation_bypass` | revocation propagates correctly |
| `provenance_poisoning` | inference cannot become evidence silently |
| `replay_attack` | replay protection is once-only |
| `trust_manipulation` | failures fail closed |
| `confused_deputy` | tool output is data, not authority |
| `cross_agent_escalation` | every interaction is untrusted until authorized |
| `policy_conflict` | conflicting policies resolve to the narrower authority |

Every scenario is automated in `firewall.research` and every defense is
verified by `test_v2_1_adversarial.py` plus the lab's own run. A
discovered violation is a regression-test seed by construction.

## Threat surface by subsystem

### Defense mesh

- **Identity spoofing**: presenting another agent's proof. The mesh
  verifies presented challenge signatures against the registry; forged
  or stale signatures deny, and the agent is restricted.
- **Authority inflation**: the mesh's capability provider is the only
  source of "can it act" and is fail-closed by default; without an
  attached SDK provider nothing can act.
- **Quarantine bypass**: quarantine routes through the v2.0 containment
  controller, which revokes through the SDK's own registry. An error
  during restriction escalates to quarantine (fail closed).

### A2A zero trust

- **Replay of challenges**: nonces are single-use and expire after
  `CHALLENGE_TTL`.
- **Wrong-agent signatures**: the challenge payload names the agent, so
  a signature by another identity fails.
- **Delegation widening**: grants are intersected with the parent's
  effective permissions; a grant outside the parent's authority raises
  at delegation time.
- **Broken lineage**: a missing ancestor or a cycle makes the
  relationship inactive (authorization denies).
- **Expired grants**: `expires_at` is checked against the clock for the
  relationship and every ancestor.

### Attack graph

- **Basis inflation**: every hop carries its basis and a path's basis is
  its weakest hop; simulated hops never masquerade as observed.
- **Non-termination**: the BFS expands each node at most once, so cyclic
  graphs (capability -> agent `holds` + reverse traversal) terminate.

### Digital twin

- **Production mutation**: the twin snapshots a serializable graph and
  works on deep copies; it holds no live registry reference.
- **Evidence inflation**: every counterfactual report is labeled
  `simulated`.

### Evidence graph

- **Silent promotion**: promotion requires an explicit call with a
  reason; the original event is never rewritten.
- **Tampering**: hash chain, ordering, causal-parent, and signature
  checks report every violation; `verified` is only returned when every
  check passes.

### Immune system

- **Model self-authorization**: a recommendation without a matching
  deterministic policy rule is skipped; high-impact stages require
  approval unless `auto_approve`.
- **Recovery bypass**: recovery is gated on verification (identity,
  posture, capability, mesh state).

### Research lab

- **Lab escapes**: every scenario runs in a fresh workspace with fresh
  registries and SDKs; nothing persists across scenarios.

## Non-threats (explicit)

- A fully compromised identity issuer or signing key.
- Physical compromise of the host running the console.
- A malicious operator/approver (they hold the highest authority by
  design).
- Side-channel attacks on the crypto primitives themselves.
