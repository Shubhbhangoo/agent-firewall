# v2.0 CLI Reference (identity / task / passport / attestation / provenance / posture / trust / lab)

All v1.7 / v1.8 / v1.9 commands keep their exact behavior. v2.0 adds:

## identity

```bash
firewall identity create <agent> [--registry identities.json]
    [--owner <owner>] [--environment <env>] [--issuer trusted-issuer]
    [--parent <agent>] [--passphrase <pw>] [--json]
firewall identity show [--registry identities.json] [--agent <agent>]
    [--passphrase <pw>] [--json]
firewall identity rotate <agent> [--registry ...] [--passphrase <pw>] [--json]
firewall identity revoke <agent> [--registry ...] [--reason <reason>]
    [--passphrase <pw>] [--json]
```

## task

```bash
firewall task create <agent> [--registry identities.json] [--state tasks.json]
    [--permissions '{"allowed_actions": ["read"]}'] [--passphrase <pw>] [--json]
firewall task delegate <task-id> <agent> [--state tasks.json]
    [--permissions '{"allowed_actions": ["read"]}'] [--json]
firewall task show [--registry ...] [--state tasks.json] [--agent <agent>] [--json]
```

## passport

```bash
firewall passport show <agent> [--registry identities.json] [--out passport.json] [--json]
firewall passport verify passport.json [--registry identities.json] [--json]
```

Exit: `0` verified, `1` failed, `2` inputs unusable.

## attestation

```bash
firewall attestation verify attestation.json [--registry identities.json] [--json]
```

The verifier distinguishes `verified` / `failed` / `unverifiable` and
never conflates them (unsupported algorithms and unknown identities are
`unverifiable`).

## provenance

```bash
firewall provenance register <kind> <name> [--state provenance.json]
    [--version <v>] [--source <url>] [--integrity <digest>] [--dependencies a,b]
firewall provenance trust <trust|suspect|revoke> <component-id>
    [--state provenance.json] [--reason <reason>]
firewall provenance show [--state provenance.json]
firewall provenance verify <component-id> <file> [--state provenance.json]
```

Registration never trusts: a component starts `unknown` and must be
trusted explicitly. `verify` compares a file's SHA-256 to the recorded
integrity digest.

## posture

```bash
firewall posture <state.json> [--agent <agent>] [--json]
```

`state.json` carries per-agent signals:

```json
{"signals": [{"agent": "agent-a", "name": "credential_access", "severity": 5, "description": "..."}]}
```

## trust

```bash
firewall trust <network.json> --agent <agent>       # what-can
firewall trust <network.json> --who <resource>      # who-can
firewall trust <network.json> --delegated <agent>   # who-delegated
firewall trust <network.json> --changed <agent>     # what-changed
firewall trust <network.json> --radius <agent>      # blast radius
```

## lab

```bash
firewall lab sweep <network.json> [--json]
firewall lab counterfactual <network.json> --agent <agent>
    [--kind compromised_agent] [--title "..."] [--added a,b]
    [--removed a,b] [--containment none|restrict|quarantine] [--json]
```

## Exit codes

`0` success / meaningful positive result · `1` meaningful negative
result (no identities/tasks/passwords, failed verification) · `2`
inputs could not be used.
