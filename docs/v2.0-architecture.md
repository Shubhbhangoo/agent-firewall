# v2.0 Architecture: the Agent Security Control Plane

## The mission

v2.0 connects every consequential agent action to the full chain:

```text
IDENTITY -> TASK -> AUTHORITY -> CAPABILITY -> PROVENANCE -> POLICY
-> DECISION -> EXECUTION -> EVIDENCE -> POSTURE -> RISK -> RESPONSE
```

The control plane answers: *who performed this action, under what
authority, for what task, using which capability/tool, according to
which policy, what happened, what evidence proves it, what posture
resulted, and what response occurred?*

## Layering (all new work is additive over v1.8/v1.9)

```text
firewall.ident       identity registry (create/rotate/revoke/retire,
                     key fingerprints, parent/child, atomic persistence)
firewall.task        task-bound authority (permission intersection,
                     delegation chains that only narrow, subtree revoke)
firewall.attest      signed, versioned attestations (alg metadata,
                     verified/failed/unverifiable)
firewall.passport    deterministic signed agent security passports
firewall.provenance  supply-chain provenance (integrity, explicit
                     trust, revocation propagation)
firewall.posture     evidence-backed continuous posture engine
firewall.trust       cross-agent trust queries + danger heuristics
firewall.lab         Security Lab 2.0 (sweep + counterfactuals)
firewall.response2   adaptive response (TTL, approval, attestation)
```

Every new module reuses the existing authorization pipeline; none of
them authorize anything. Identity, tasks, and posture feed *context*;
`FirewallSDK.authorize()` alone decides.

## Identity model (firewall.ident)

- An `Identity` records agent_id, issuer, identity_version, owner,
  environment, status (`active`/`revoked`/`retired`), public key,
  key fingerprint, parent_agent, and metadata.
- The registry persists atomically. Private keys are stored encrypted
  under a passphrase (PBKDF2 + AES-GCM) or held in memory only; they
  never enter artifacts, passports, or attestations.
- Verification is honest: `verify()` fails for unknown, revoked,
  retired, or rotated-out keys. Identity never implies authorization.

## Task-bound authority (firewall.task)

- A `Task` carries permissions and a lifecycle. `delegate()` narrows:
  the child's effective permissions are the intersection of the
  parent's and the grant, so a delegation chain (A -> B -> C) can never
  increase authority.
- Root revocation propagates to the whole subtree; expiration is
  enforced at check time; a lineage cycle fails closed.

## Passport (firewall.passport)

A passport is a deterministic, versioned, signed document: identity +
posture + tasks + capabilities + delegated authority + provenance +
reach + incidents + containment, signed by the agent identity key.
Verification distinguishes `verified` / `failed` / `unverifiable`.
No private keys inside.

## Attestation (firewall.attest)

Signed statements about identity, authority, delegation, decisions,
execution events, posture transitions, and containment. `alg` metadata
makes algorithms replaceable (post-quantum migration without changing
the model); the verifier returns `unverifiable` for unsupported
algorithms rather than guessing.

## Supply-chain provenance (firewall.provenance)

Components (models, tools, MCP servers, skills, plugins, packages,
adapters, configuration, policies) carry integrity digests and
explicit trust state. A name is never trust; revocation of a component
marks its dependents untrusted.

## Posture (firewall.posture)

Evidence-backed states: unknown -> healthy -> degraded -> suspicious ->
high_risk -> compromised -> contained -> recovering -> retired. Every
transition is produced by a named signal with evidence; `explain()`
answers why, which evidence, and what should be revoked.

## Trust graph and lab (firewall.trust, firewall.lab)

`TrustGraph` answers what-can, who-can, who-delegated, what-changed,
blast-radius, and path, plus inferred danger detection. `SecurityLab`
sweeps the whole environment (attack surface, dangers, sensitive
resources, containment opportunities, policy weaknesses, supply chain)
and answers counterfactuals in isolated workspaces.

## Adaptive response (firewall.response2)

Evidence-backed graduated response with response TTL/expiration, human
approval for high-impact stages, audit, and an optional signed
attestation of every response decision. Authorization remains the final
enforcement boundary.

## Compatibility

Everything is additive: v1.8 artifacts, v1.9 artifacts, CLI commands,
SDK APIs, integrations, and browser routes keep their exact behavior.
The full regression suite (2,700+ tests) continues to pass.
