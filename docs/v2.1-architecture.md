# v2.1 Architecture: the Autonomous Agent Defense Layer

v2.0 established the **Agent Security Control Plane**: identity, task-bound
authority, passports, provenance, posture, trust, lab, and response layered
over the canonical `FirewallSDK` authorization pipeline.

v2.1 evolves that control plane into an **active, continuously operating
defense system** for autonomous agent ecosystems. It adds nine new
subsystems, all of which sit **above** the v2.0 authorization boundary and
reuse its primitives. Nothing in v2.1 can authorize, bypass, or relax a
decision made by the v2.0 pipeline.

## 1. Reused v2.0 primitives

| v2.0 primitive | reused by |
| --- | --- |
| `firewall.ident.IdentityRegistry` | defense mesh identity verification, a2a mutual authentication, evidence signing |
| `firewall.attest.AttestationAuthority` | signed audit of mesh transitions, immune actions, evidence promotion |
| `firewall.task.TaskRegistry` | task-bound delegation, delegation-chain verification |
| `firewall.network.AgentNetworkGraph` + `AttackPathAnalyzer` | attack graph source facts, twin baselines |
| `firewall.trust.TrustGraph` | trust evaluation and blast-radius queries |
| `firewall.lab.SecurityLab` | counterfactual orchestration inside the twin |
| `firewall.posture.PostureEngine` | immune detection input, mesh state signals |
| `firewall.containment.ContainmentController` | quarantine, recovery, fail-closed enforcement |
| `firewall.response2.AdaptiveResponder` | graduated response policies in the immune system |
| `firewall.recorder` + `firewall.artifact` | evidence graph source of signed observations |
| `firewall.sdk.FirewallSDK` | the one and only authorization authority |
| `firewall.network.model.Provenance` | the five bases: observed/derived/inferred/simulated/unknown |

## 2. Security boundaries

The v2.1 layering:

```text
  research lab (adversarial testing of everything below)
  intel engine (correlation -> explainable hypotheses, advisory only)
  immune system (OBSERVE -> VERIFY loop; policy-driven, audited actions)
  evidence graph (tamper-evident, signed event log; kinds never conflated)
  digital twin (isolated counterfactuals; never touches live state)
  attack graph (continuous reachability/escalation analysis)
  a2a zero trust (mutual auth, scoped relationships)
  defense mesh (live identity/trust/capability evaluation, quarantine)
        |
        v
  v2.0 control plane (identity, task, provenance, posture, trust, lab)
        |
        v
  FirewallSDK authorization pipeline (the only authority)
```

Three absolute boundaries:

1. **No v2.1 module authorizes.** Every action check routes through the
   v2.0 pipeline (or fails closed). The mesh, twin, immune system, and
   intelligence engine produce analysis and *recommendations*; only the
   SDK's `authorize()` and the explicit policy rules in the immune system
   can execute a defensive action, and those actions go through the SDK's
   own revocation/risk mechanisms.
2. **Simulation cannot mutate production.** The twin snapshots
   serializable state and works on deep copies. It has no reference to any
   live registry object that a counterfactual could mutate.
3. **Inference never becomes evidence.** The evidence graph's five kinds
   (`observed`, `inference`, `prediction`, `simulation`, `unknown`) are
   structurally distinct. Promotion to `observed` requires an explicit,
   signed promotion event with a `promoted_from` reference. A promotion is
   a deliberate act, never an implicit upgrade.

## 3. Circular-dependency check

`firewall.defense` depends on `ident`, `containment`, `posture`, `sdk`,
and `attest`. `firewall.a2a` depends on `ident`, `task`, `attest`, and an
optional `sdk` provider. `firewall.attackgraph` depends on `network` and
`trust` (read-only). `firewall.twin` depends on `attackgraph` and `lab`
(read-only). `firewall.evidence_graph` depends on `ident`/`attest` for
signing only. `firewall.immune` depends on `defense`, `twin`,
`evidence_graph`, `posture`, `containment`, `response2`. `firewall.intel`
depends on `network`, `trust`, `posture`, `evidence_graph`, `attackgraph`.
`firewall.research` depends on everything above it and on `hypothesis` for
property tests. No dependency cycle exists; the CLI and UI are the only
layers that import across all of them.

## 4. v2.1 invariants

1. Identity does not equal authority. (v2.0, preserved)
2. Credentials do not automatically become capabilities. (v2.0, preserved)
3. Delegation can only narrow authority - in tasks, capabilities, and
   agent-to-agent relationships. effective(child) is a subset of
   effective(parent).
4. Revocation propagates recursively: revoking an a2a relationship revokes
   every relationship derived from it; revoking an identity revokes its
   mesh membership; revoking a capability revokes its lineage (v2.0).
5. Simulation cannot mutate production state. The twin holds no live
   references; every counterfactual runs on a copy.
6. Inference cannot become evidence without explicit provenance. Evidence
   kinds are structural and promotion is a signed, explicit event.
7. Model output cannot authorize itself. The immune system's reasoner is
   advisory; execution requires a matching deterministic policy rule.
8. Every security decision is explainable and auditable: decisions carry a
   reason, the evidence that fed them, and an audit record in the evidence
   graph.
9. Security failures fail closed wherever authorization is concerned:
   unknown agents, broken chains, unverifiable evidence, and malformed
   state all deny.
10. A delegated capability never gains authority compared with its parent
    (capability firewall 2.0 constraint narrowing).

## 5. New subsystems (summary)

| subsystem | module | what it does |
| --- | --- | --- |
| **Defense Mesh** | `firewall.defense` | continuously evaluates identity, trust, and capability state per agent; quarantines compromised agents through the v2.0 containment controller; audited recovery and re-entry; fail-closed. |
| **A2A Zero Trust** | `firewall.a2a` | mutual cryptographic authentication, scoped relationships, task-bound delegation, expiring grants, recursive revocation, trust establishment/teardown. |
| **Attack Graph** | `firewall.attackgraph` | continuous attack-path engine over agents/identities/tasks/authorities/capabilities/tools/resources/delegations/provenance/policies/trust/incidents; escalation paths, chokepoints, blast radius; every edge labeled observed/derived/inferred/simulated. |
| **Digital Twin** | `firewall.twin` | isolated counterfactuals (compromise, revocation, untrusted tool, delegation, credential exposure) returning attack paths, reachability deltas, blast radius, containment opportunities, policy changes, risk deltas. |
| **Evidence Graph** | `firewall.evidence_graph` | signed, hash-linked events with causal ordering, tamper detection, replayable timelines, and explicit evidence kinds. |
| **Capability Firewall 2.0** | `firewall.capability2` | composable constraints over resource/scope/action/time/context/identity/task/lineage/provenance/environment; safe attenuation; delegation never widens. |
| **Immune System** | `firewall.immune` | OBSERVE -> DETECT -> REASON -> SIMULATE -> CONTAIN -> RECOVER -> VERIFY loop; model output advisory only; execution deterministic and policy-driven. |
| **Research Lab 3.0** | `firewall.research` | adversarial testing of the control plane itself; every discovered violation becomes a regression test; property-based testing. |
| **Intelligence Engine** | `firewall.intel` | correlates evidence/behavior/trust/provenance/posture/attack paths/policy/response history into explainable hypotheses with recommended containment. |

## 6. Non-guarantees (explicit)

- v2.1 does **not** detect every intrusion; heuristics are labeled
  `inferred` and are never presented as observation.
- The twin's counterfactuals are **simulations**: a predicted path is not
  a recorded fact, and reachability is not exploitability.
- The immune system's containment is as good as the evidence feeding it;
  a deterministic policy rule cannot be overridden by a model's opinion.
- Nothing in v2.1 defends against a fully compromised identity issuer or
  a compromised signing key - that is out of scope, same as v2.0.
