# v2.2 Threat Model

v2.2 assumes the v2.0 and v2.1 threat models and adds the threats that
arise from authority being **long-lived** and from the platform's own
security machinery being the target.

Two adversary classes are new here:

1. **The attacker who waits.** Authority granted at T1 was correct at T1.
   The attack is to keep using it after the state it rested on has
   changed — an identity revoked, a task expired, a posture collapsed, an
   ancestor capability withdrawn.
2. **The attacker who attacks the checker.** If a verification subsystem
   can be made to fail silently, or to report a reassuring answer when it
   could not check, then breaking the checker is cheaper than defeating the
   control it protects.

## Trust assumptions

1. `FirewallSDK.authorize()` is trusted and remains the **only** decision
   authority. No v2.2 subsystem can allow, deny, or relax a decision it
   makes. Continuous authorization is more restrictive than the canonical
   decision or identical to it, never less.
2. Identity issuers and their signing keys are trusted. A fully
   compromised issuer is out of scope.
3. A capability's **signature** is trusted. The mutable delegation lineage
   registry is **not**: it is writable by anything holding the SDK, so
   where the two disagree the signature decides.
4. Evidence signers are trusted to sign what they observe.
5. Model output is never trusted to authorize anything.
6. A signed checkpoint anchor is trusted. Without one, an evidence chain
   cannot prove it has not been truncated.

## Adversaries new in v2.2

| adversary | capability | defended by |
| --- | --- | --- |
| **Stale-authority holder** | keeps using a decision after identity, task, capability, delegation, provenance, posture, risk, trust, policy, environment, resource or incident state changed | `ContinuousAuthorizationEngine` re-runs `authorize()` on any of fifteen triggers and compares verdicts |
| **Monitor blinder** | breaks or removes a security dependency so the sweep cannot see the change | `PROBE_FAILED` is distinct from `UNKNOWN`; a configured dependency that raises lands in `degraded_dependencies` and turns an allow into `security_dependency_unavailable` |
| **Lineage rewriter** | edits the mutable delegation registry to rebind a legitimately signed child to a wider parent, or to drop the edge so the child authorizes as a root | `_verify_signed_lineage_agreement` refuses both; the signed `parent_fingerprint` decides |
| **Untrusted-input injector** | supplies an action name from tool output that crashes the gate chain instead of being denied | `invalid_action` is a verdict; malformed input never raises in place of deciding (`FAIL_CLOSED`, input probes) |
| **Registry mutator** | reaches a subsystem's reference to the live capability dict and injects a forged ancestor or deletes an inconvenient one | `known_capabilities()` returns a `MappingProxyType`; `CONTROL_PLANE_INTEGRITY` forbids private access from outside `sdk.py` |
| **Snapshot pinner** | holds a copy of the capability registry taken before a revocation | `known_capabilities()` is a live view, not a copy |
| **Tail truncator** | deletes the end of an evidence chain, leaving a shorter internally consistent one | `TRUNCATED_CHAIN` against a signed anchor. **Undetectable without one** — stated as a limit, not a guarantee |
| **Anchor forger** | forges, substitutes, reorders or removes a checkpoint so truncation passes | `REPLACED_CHECKPOINT`, `ANCHOR_MISMATCH` |
| **Evidence substituter** | imports a foreign chain under a local chain's id, or re-imports a doctored copy of a local event | `import_chain` quarantines; refuses a known chain id, refuses any known event id, writes nothing until every check passes |
| **Unattributed importer** | supplies an export with no verifiable signer and relies on it being stored as "unverified" | `verify=True` requires the signer and refuses the import; an evidence store that remembers it could not check will be read as if it had |
| **Claim-source liar** | tells the identity registry one thing, the task registry another, and the posture engine a third | the deception engine compares eight independent claim classes and reports `CONTRADICTED` without picking a winner |
| **Clean-profile forger** | makes discrepancy checks raise so the profile comes back empty and low-risk | every raising check emits a `DiscrepancyType.UNKNOWN` signal plus a named gap; `risk_level` defaults to `"unknown"` and can never be `"low"` while a required fact is unestablished |
| **Invariant defeater** | breaks a checker so the suite passes vacuously | `UNVERIFIABLE` is falsy, makes the report falsy, and makes `assert_all` raise; a checker that raises becomes `UNVERIFIABLE`, never `HOLDS` |
| **Second-authority smuggler** | adds a subsystem that constructs its own verdict, or a gate that can allow | `AUTHORIZATION_UNIQUENESS` and `MODEL_NON_AUTHORITY` are checked over the source tree in CI |
| **Vocabulary forker** | introduces a second provenance enum so `inferred` in one subsystem compares equal to `observed` in another | `PROVENANCE_INTEGRITY`; `firewall.platform.provenance` re-exports rather than redeclares |

### Added in v2.5

| adversary | capability | defended by |
| --- | --- | --- |
| **Dependency saboteur** | makes one of the boundary's own reads fail — refusal state, risk state, issuer trust, revocation, delegation lineage — so `authorize()` raises and the caller's `except Exception` decides what happens to an unauthorized request | each read is a denial naming the dependency: `refusal_state_unavailable:{Type}`, `revocation_state_unavailable:{Type}`, and so on; nine `FAIL_CLOSED` probes exercise the paths, each with its own control |
| **Evidence breaker** | makes the audit write on the *denial* path fail, destroying a refusal that already existed | the verdict is unchanged and the loss travels with it in `trace["evidence_error"]`; on the allow path the failure becomes `evidence_unavailable:{Type}` |
| **Time-authority splitter** | supplies a correct signature-only verifier that leaves expiry to the firewall's time gate, then presents an expired capability | `_gate_time` denies `clock_unavailable:{cause}` rather than abstaining; before v2.5 the gate skipped the window check and returned `authorized`. See [v2.5-boundary.md](v2.5-boundary.md) |

## Attack scenarios and what fails if they succeed

| scenario | property broken |
| --- | --- |
| authority survives its own revocation | revocation propagates and is never undone (`REVOCATION_MONOTONICITY`) |
| a delegate authorizes as a root | delegation only narrows (`DELEGATION_MONOTONICITY`) |
| a signed child is checked against a wider parent | effective authority is the intersection of the chain |
| a crash substitutes for a denial | the authorization path never raises in place of deciding (`FAIL_CLOSED`; true of unavailable state only from v2.5 — [v2.5-boundary.md](v2.5-boundary.md)) |
| an unchecked subsystem reports "fine" | unknown is not trusted |
| a simulation leaves a trace in production | simulation is not observation (`SIMULATION_ISOLATION`) |
| an inferred finding is read as recorded | inference is not observation (`PROVENANCE_INTEGRITY`) |
| a risk score decides | model output is not authority (`MODEL_NON_AUTHORITY`) |
| a policy transformation widens authority | policy transformations only narrow (`POLICY_NON_WIDENING`) |

Each right-hand entry names a machine-checkable invariant where one
exists; see [v2.2-invariants.md](v2.2-invariants.md). The five
state-dependent invariants require an exercised SDK, which the test suite
provides and a source-only CI run explicitly does not.

## What v2.2 does not defend against

- A compromised identity issuer or signing key.
- An attacker with write access to the process's own memory.
- Truncation of an evidence chain with no signed anchor.
- Identification of *which* field of a replaced event changed.
- Distinguishing a rotated-out signing key from one that never existed.
- Change classes whose subsystem was never injected into continuous
  authorization. Undetectable is not safe, and the API makes the
  dependency explicit rather than defaulting it so this is visible at the
  call site.
- Policy changes outside the trusted-issuer set and the delegation-depth
  ceiling, unless a real `continuous_auth_policy_version_provider` is
  injected.
- Exploitability. Reachability in the attack graph, a weakness finding in
  the adversarial search, and a twin counterfactual are all analysis. A
  predicted path is not a recorded fact.
