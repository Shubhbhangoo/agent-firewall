# Agent Firewall v1.0 API Contract

## Purpose

v1.0 freezes the public API surface of Agent Firewall so applications can depend on stable interfaces.

The security model may continue to receive internal hardening, but public behavior should not change without an intentional compatibility decision.

## Stable Public API

The following interfaces are intended to be stable in v1.0:

### Core

- `Firewall`
- `Decision`
- `FirewallSDK`

### Capabilities

- `Capability`
- `CapabilityVerifier`
- `capability_fingerprint`
- `generate_capability_key_pair`
- `sign_capability`

### Delegation

- `Delegation`

### Revocation

- `RevocationRegistry`
- `RevocationRecord`
- revocation-related public exceptions

### Lifecycle

- `LifecycleEvent`
- `LifecycleEventType`
- `LifecycleRecorder`

Stable lifecycle event types:

```text
ISSUED
DELEGATED
ATTENUATED
USED
REPLAYED
REVOKED
DENIED
EXPIRED
````

Lifecycle history is observational data and must not itself grant authority.

### Persistence

* `LifecycleStore`
* `SQLiteLifecycleStore`
* public lifecycle persistence exceptions

Persistent lifecycle state must survive normal SDK restart.

Persistent revocation state must survive normal SDK restart.

Persistence failures must fail explicitly rather than silently producing an inconsistent security state.

### Developer APIs

* `protect`
* `ProtectedTool`
* `protect_tool`

### Adapters

* `GenericToolAdapter`
* `GenericToolCall`
* `generic_tool`
* `OpenAITool`
* `openai_tool`
* `AnthropicTool`
* `anthropic_tool`
* `normalize_tool_call`

### Investigation

* `LifecycleExplanation`
* `explain`
* `explain_request`

## Security Contract

Public adapters must not implement an independent authorization system.

Authorization must ultimately flow through the Agent Firewall security core.

A convenience API must never:

* create unauthorized capabilities
* bypass signature verification
* bypass namespace checks
* bypass constraints
* bypass revocation
* bypass expiration
* bypass replay protection
* execute a denied request

## Capability Compatibility

Capability fingerprints are stable security identities.

Reissuing a capability creates a distinct capability identity unless the underlying capability data and signing semantics intentionally produce the same identity.

Delegation and attenuation must not increase authority.

## Lifecycle Compatibility

Lifecycle event types are stable:

```text
ISSUED
DELEGATED
ATTENUATED
USED
REPLAYED
REVOKED
DENIED
EXPIRED
```

Lifecycle history is observational data and must not itself grant authority.

## Persistence Compatibility

Persistent lifecycle state must survive normal SDK restart.

Persistent revocation state must survive normal SDK restart.

Persistence failures must fail explicitly rather than silently producing an inconsistent security state.

## CLI Compatibility

The `firewall` command is part of the public developer interface.

Current commands:

```text
firewall init
firewall validate
firewall inspect-token
firewall explain
```

Command behavior should remain backwards compatible across v1.x releases.

## Versioning Policy

v1.0 follows semantic-versioning expectations for public APIs.

Breaking changes require a major-version transition.

Security fixes may change internal implementation without changing public semantics.

Experimental functionality may be introduced only when clearly marked as experimental and excluded from the stable contract.

## Compatibility Rule

When internal improvements conflict with an existing stable public contract, preserve the public contract unless the existing behavior creates a demonstrated security vulnerability.

Security takes precedence over compatibility when necessary to prevent an authorization bypass.
