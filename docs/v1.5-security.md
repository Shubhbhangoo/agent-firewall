# v1.5 Security Model

v1.5 hardens the boundary between an AI agent and the authority it can exercise through tools.

## Session capabilities

Session capabilities are minted for a specific agent and tool with a fresh TTL-derived expiration. The tool binding is part of the signed capability, so a capability minted for `filesystem.read` cannot be reused for `network.request`.

## Delegation lineage

Delegation is represented as:

```text
child -> parent -> ancestor -> root
```

Authorization evaluates the effective authority of the complete chain. Missing ancestors fail closed. Revocation of a root or intermediate capability propagates to descendants, while unrelated branches remain valid.

## Transitive budgets

A cumulative delegation budget is owned by the root capability fingerprint. Parent, child, and grandchild capabilities draw from that same budget:

```text
root budget = 100
    |
    +-- agent-b: 60
    |
    +-- agent-c: 40
    |
    +-- next request: denied
```

Separate root capabilities have separate budgets. Budget reservations are protected against concurrent overspend.

## Tool output boundary

Protected tool results are marked as untrusted data. Instructions returned by a file, PDF, webpage, MCP tool, or other retrieval source do not become authorization merely because they are expressed as instructions.

The boundary is:

```text
tool execution
      |
      v
UNTRUSTED DATA
      |
      v
agent context
```

The SDK does not treat tool output as a capability, policy, grant, or revocation command.

## Authorization traces

Authorization results expose minimal traces for auditability:

```json
{
  "capability_id": "...",
  "agent": "agent-a",
  "action": "filesystem.write",
  "reason": "namespace_denied",
  "tool": "filesystem.read"
}
```

Traces intentionally exclude signatures, public keys, raw request payloads, and complete constraint data.

## Cross-agent isolation

Session capabilities, delegation lineage budgets, revocation state, and authorization traces remain associated with their concrete capability and agent identity. A capability issued to one agent does not become another agent's authority merely through context reuse.

## Numeric validation

Security-sensitive numeric inputs must be finite. `NaN`, positive infinity, and negative infinity are rejected for capability timestamps, verifier clocks, session TTLs, and delegation budget amounts.

## Verification strategy

The v1.5 security regression suite includes dedicated coverage for:

- session capability minting and lifecycle
- tool binding
- untrusted tool output and prompt injection
- authorization traces
- transitive delegation budgets and concurrency
- multi-level revocation propagation
- cross-agent isolation
- non-finite numeric validation

The complete test suite should be run before each release build with:

```bash
pytest -q
```
