# v3.0 performance: what proving the security state coherent costs

Methodology follows the suite's standard (see `firewall/benchmarks.py`):
warmup, then `repeats` timed calls reported as median and p95 of
`time.perf_counter`; `operations_per_second` derives from the median. All
figures below are from one development machine (CPython 3.10, Windows 10,
AMD64) and are directional, not a benchmark. Run `python -m
firewall.benchmarks state` locally for current numbers.

## What is measured

The v3.0 guarantee is paid on two sides. The ALLOW path verifies the live
canonical digest of the in-domain stores against the hash-chained
commitment head once per allow; every legitimate in-domain write ends by
committing the resulting state to the chain. The `state` group measures
both, plus the number an operator actually needs — how often requests are
refused while the stores are being silently mutated:

| benchmark | what one operation does |
| --- | --- |
| `state_commit_authorize` | `FirewallSDK.authorize()` on the shipped v3.0 path: one allow, ending with the digest-of-revocation+issuer-trust+lineage+depth compared against the chain head under the journal lock |
| `state_commit_transition` | one legitimate in-domain write: issue a capability and revoke it through the declared path, so the journal brackets the mutation, re-reads the whole canonical state and appends one linked, state-anchored commitment |
| `state_commit_tamper` | eight threads authorizing while one thread silently forgets revocations directly in the registry dict (a store edit with no write path — the class of attack the epoch cannot see) and heals through the legitimate path, so the measured figure is the price of the open window |

## Results (directional)

| layer | median ms/op | ops/s |
| --- | --- | --- |
| `state_commit_authorize` (allow + coherence proof) | 27.8 | ~3,600 |
| `state_commit_transition` (issue + revoke + commitment) | 21.9 | ~2,300 |
| `state_commit_tamper` (per authorize under sustained silent mutation) | 46.2 | ~690 |

Readings from the run that produced this doc:

- `state_commit_authorize`: 100 ops per call, median 27.8 ms/call
  (~3,595 ops/s), p95 40.1 ms.
- `state_commit_transition`: 50 ops per call, median 21.9 ms/call
  (~2,286 ops/s), p95 31.6 ms; `links_appended` 300 — every transition
  committed exactly one link, across the warmup and five timed repeats.
- `state_commit_tamper`: 8 threads x 40 authorizations, median 46.2 ms,
  **denied_fraction 0.44**, `errors 0`, all denials named
  `state_incoherent:*`.

## Reading the numbers

- **An allow with proof is about the same price as an allow.** The
  v2.9 reference (`effect_authorize`) was ~26.9 ms/op on the same
  machine; the v3.0 allow with the coherence gate is ~27.8 ms/op. The
  canonical digest over four small stores, compared once under one
  lock, is not the dominant cost of a request.
- **A committed transition costs about one digest write.** Issue-plus-
  revoke commits two transitions (the issuance registers lineage state)
  in ~22 ms/call for 50 operations. The journal work is per-transition,
  paid by operators and revokers, never by requests.
- **The tamper number is a worst case by construction, and it is the
  number that matters.** 44% of requests were refused while a tamperer
  silently forgot revocations and healed in a loop, with zero errors
  and every refusal a named `state_incoherent` denial. That is the price
  of never relying on a security state the firewall cannot prove is
  coherent: when the state cannot be accounted for, the boundary refuses
  rather than guesses. Requests that were allowed landed in the windows
  where the live state matched the chain head at their commit instant —
  which is exactly the linearization the mechanism provides.
- **The refusal path cannot manufacture an allow.** `errors` must be
  zero in every run, and the only effect of a broken or missing journal
  is a denial. Nothing here may be used to weaken a check to produce a
  better number; the legitimate lever is *where* the journal lives (a
  file the attested stores cannot reach), not whether coherence is
  verified.
