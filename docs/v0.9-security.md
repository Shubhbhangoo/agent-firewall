# Agent Firewall v0.9 Security Notes

## Security model

Agent Firewall treats tool execution as an authorization boundary. A protected operation must be authorized before the underlying handler is allowed to run.

The core decision path combines the capability, agent identity, namespace, constraints, validity period, replay state, and applicable policy.

## Tool adapters

OpenAI, Anthropic, and generic tool adapters are translation layers. They normalize provider-specific tool calls and forward them into the existing authorization path.

Adapters do not mint authority, weaken namespace checks, or replace capability verification.

## Protected handlers

`ProtectedTool` and `protect()` establish a handler boundary:

```text
provider/tool call
        |
        v
normalize input
        |
        v
capability authorization
        |
   +----+----+
   |         |
 allow      deny
   |         |
   v         v
handler   PermissionError
```

The important invariant is that authorization happens before handler execution.

## Lifecycle evidence

Lifecycle events provide an operational history of capability state and use. Explanation tooling reads this history for investigation and debugging. It does not become a second authorization engine.

## Persistence

Lifecycle and revocation state can be persisted so that restart does not silently erase security state. Persistent storage should be protected with the same operational controls applied to other security-sensitive application data.

## Property-based testing

v0.9 supplements example-based and adversarial tests with Hypothesis-generated inputs. The property suite exercises normalization, snapshot behavior, lifecycle persistence, authorization stability, and capability transport round trips.

Property-based tests are not a substitute for threat modeling or targeted adversarial tests. They are an additional way to explore unexpected input combinations.

## Deployment considerations

Before production use, review:

- trusted capability issuers and signing keys
- agent identity configuration
- capability scope and constraints
- replay configuration and nonce handling
- lifecycle and revocation storage permissions
- policy and approval configuration
- audit-log handling and retention
- secret handling and evidence redaction

The benchmark numbers in `v0.9-benchmarks.md` are performance measurements, not security guarantees.
