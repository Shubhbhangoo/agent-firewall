# v2.1 CLI Reference

All v2.0 and v1.9 commands remain available. v2.1 adds nine command
families. Exit-code contract is unchanged: `0` success / meaningful
positive result, `1` meaningful negative result, `2` usage/input error.

## defense - real-time defense mesh

```text
firewall defense evaluate <agent> [--registry identities.json]
                             [--state mesh.json] [--json]
firewall defense quarantine <agent> --reason <reason> [--actor cli]
                             [--registry ...] [--state mesh.json] [--json]
firewall defense recover <agent> --reason <reason> [--actor cli] ...
firewall defense reenter <agent> --reason <reason> [--actor cli] ...
firewall defense state [--agent <agent>] [--registry ...] [--state mesh.json] [--json]
```

The CLI attaches a live `FirewallSDK` so capability evaluation and
quarantine exercise the real pipeline. Every registered active identity
receives a scoped operating capability from the SDK's key.

`evaluate` exits `1` for an unknown identity (fail closed). `quarantine`
requires a reason; `recover` only works from `quarantined`; `reenter`
re-verifies identity, posture, recovery freshness, and the capability
provider.

## delegate - agent-to-agent zero trust

```text
firewall delegate establish --initiator <a> --responder <b>
                 --permissions '<json>' [--ttl <seconds>]
                 [--registry ...] [--state a2a.json]
firewall delegate grant --relationship <id> --responder <b>
                 --permissions '<json>' ...
firewall delegate revoke --relationship <id> --reason <reason> ...
firewall delegate teardown --a <agent> --b <agent> --reason <reason> ...
firewall delegate authorize --actor <a> --target <b> --action <action>
                 [--request '<json>'] ...
firewall delegate graph ...
```

`establish` requires both identities to be active. `grant` narrows by
intersection. `authorize` returns `0` when allowed, `1` when denied.

## capability - Capability Firewall 2.0

```text
firewall capability eval <policy.json> '<request-json>'
firewall capability attenuate <policy.json> --out <out.json>
                 [--narrowing '<json>']
firewall capability delegate <policy.json> --out <out.json>
                 [--narrowing '<json>']
```

A policy file is a serialized `Capability2`:

```json
{
  "capability": "payments.send",
  "constraints": {
    "resource": "payments",
    "action": ["send", "refund"],
    "time": {"not_after": 1900000000},
    "identity": {"agent_id": "alice"},
    "lineage": {"max_depth": 2},
    "environment": {"env": "prod"}
  }
}
```

`eval` exits `1` on denial; `attenuate`/`delegate` refuse any change
that would widen the policy.

## attack-graph - autonomous attack-path engine

```text
firewall attack-graph build <network-state.json> [--out attack-graph.json]
firewall attack-graph paths <graph.json> --target <target> [--max-hops 8]
firewall attack-graph findings <graph.json>
firewall attack-graph summarize <graph.json>
```

`build` converts a v1.9 network state file into the attack graph.
`paths` reports each hop with its basis (observed/derived/inferred/
simulated) - a path's basis is its weakest hop.

## twin - security digital twin

```text
firewall twin <network-state.json> --kind <kind> [flags...]
  kinds: compromised_agent (--agent)
         revoked_capability (--agent --capability)
         untrusted_tool (--tool)
         delegated_authority (--grantor --grantee)
         exposed_credential (--agent [--credential])
```

Every report is labeled `simulated` and never mutates production state.

## evidence - cryptographic evidence graph

```text
firewall evidence append --state evidence.json --kind <kind>
                 --subject <s> --type <t> [--payload '<json>']
                 [--registry ... --signer-agent <agent>]
firewall evidence verify --state evidence.json [--registry ... --signer-agent <agent>]
firewall evidence timeline --state evidence.json --subject <s>
firewall evidence promote --state evidence.json --event-id <id> --reason <reason>
```

Kinds: `observed | inference | prediction | simulation | unknown`.
Without a signer, events are unsigned and verification reports
`unverifiable`. `promote` creates a new observed event referencing the
original; it never rewrites it.

## immune - agent immune system

```text
firewall immune demo [--policy policy.json] [--json]
firewall immune state [--json]
```

`demo` runs one OBSERVE->DETECT->REASON->SIMULATE->CONTAIN->VERIFY cycle
over a self-contained workspace. A policy file lists rules:

```json
{"rules": [{"rule_id": "compromised_posture", "stage": "quarantine",
            "min_severity": "high", "auto_approve": false}]}
```

## research - Security Research Lab 3.0

```text
firewall research run [--scenario <name>] [--json]
firewall research properties [--json]
firewall research report [--out report.json] [--json]
```

`run` executes all 11 adversarial scenarios in isolated workspaces and
exits `1` if any defense is defeated (each violation is a regression-test
seed). `properties` runs the hypothesis property suite.

## recover - mesh recovery

```text
firewall recover <agent> --reason <reason> [--actor cli]
             [--registry ...] [--state mesh.json] [--json]
```

Begins mesh recovery then attempts re-entry; exits `0` only when
re-entry succeeds.
