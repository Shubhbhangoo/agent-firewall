# v1.8 Security Model

## The idea

> An agent's security history should be something that can be recorded,
> verified, replayed, investigated, and shared without requiring trust
> in the original application or dashboard.

v1.8 turns Agent Firewall into a portable, cryptographically verifiable
security and accountability layer for autonomous agents. The recorded
history is a **flight recorder + security ledger + replay laboratory**,
not another authorization engine.

## Architecture

```text
signals / history / analysis
             |
             v
      security context
             |
             v
existing authoritative authorization (FirewallSDK / North Star)
             |
             v
        final decision
```

Everything new in v1.8 sits **above** the existing authorization
pipeline. Nothing it adds can ever bypass, replace, or relax a decision:

- `firewall.recorder` -- observational. Records decisions only after
  they exist; a recording failure is swallowed and can never break an
  authorization.
- `firewall.verify` -- read-only. Recomputes hashes and signatures.
- `firewall.timeline` / `firewall.replaylab` / `firewall.incident` --
  read-only projections over recorded events and throwaway replay
  workspaces.
- `firewall.containment` -- the only new write path. It changes the
  *inputs* the real pipeline reasons about (revocation registry, risk
  context) through the SDK's public APIs. A contained agent is contained
  because `authorize()` denies it, not because the controller says so.

## The security boundary (non-negotiable)

The system must never allow analysis, replay, graph, or AI-facing
functionality to bypass:

- cryptographic verification
- capability authority
- issuer trust
- revocation
- delegation validation
- North Star
- fail-closed semantics

There is no "AI says safe -> allow" path, and there never will be. The
only way to allow an action is the existing authorization pipeline.

## Flight recorder guarantees

- **Append-only, tamper-evident.** SHA-256 hash chain; every event
  commits to every earlier event. Edits, deletions, reorders, and
  injections are detectable.
- **Authenticated.** Ed25519 signed checkpoints; the artifact embeds
  only the public key. Private keys never enter an artifact.
- **Secrets stay out.** Material facts only; credential-shaped values
  are redacted before hashing and the redaction is declared, so missing
  evidence is never mistaken for trustworthy evidence.
- **Explicit lifecycle.** A session must be finalized to verify as
  `verified`/`redacted`; anything else is `incomplete` or `failed`.
- **Bounded cost.** One hash per event, a checkpoint every N events.

## Verification states (never conflated)

`verified` · `failed` · `unverifiable` · `incomplete` · `redacted`

Missing evidence is reported, never promoted to trustworthy evidence.
A failed artifact must not be treated as evidence at all.

## Containment discipline

Every containment action is:

- **authorized** -- routed through the control plane's bearer-token gate
- **authenticated** -- an actor identity is recorded
- **audited** -- recorded in the control-plane audit and the flight
  recorder
- **explainable** -- a reason is required
- **reversible where appropriate** -- recovery re-issues equivalent
  authority and resets runtime risk
- **fail-closed** -- an error during restriction escalates to
  quarantine; it never leaves an agent unrestricted

## Trust boundaries

- **Recorder identity is a root of trust decision.** An artifact proves
  internal consistency; pinning the recorder fingerprint
  (`--expect-recorder`) is how a verifier decides who the artifact may
  have come from.
- **The console remains a trusted local developer interface.** Loopback
  binding, bearer token, audited writes, and read-only analysis routes
  that never touch the live SDK.
- **Case/artifact redaction keeps sharing safe.** Redaction export
  re-hashes and re-signs under a fresh identity; the original private
  key is never needed.

## What the new code never does

- Never authorizes anything (recorder, verifier, timeline, graph,
  replay lab, incident packages).
- Never reads private keys into an artifact.
- Never lets replay or counterfactual analysis affect a live SDK.
- Never lets containment bypass `authorize()`.
- Never conflates observed / replayed / simulated / counterfactual /
  unverifiable.
- Never silently treats missing evidence as trustworthy.
