# v2.0 Security Boundaries

## The complete chain

v2.0's job is to make this chain credible and independently verifiable:

```text
WHO IS THE AGENT?            -> identity (signed, lifecycle-managed)
WHAT TASK?                   -> task-bound authority
WHAT AUTHORITY?              -> capabilities / delegated tasks
WHO DELEGATED?               -> task lineage + trust graph
WHAT DOES IT TRUST?          -> supply-chain provenance
WHAT POLICY APPLIES?         -> the SDK's own policy gates
WHAT DID IT ATTEMPT?         -> recorded authorization events
WAS IT AUTHORIZED?           -> FirewallSDK.authorize() (unchanged)
WHAT HAPPENED?               -> recorder + execution events
WHAT EVIDENCE PROVES IT?     -> .afw artifacts (v1.8)
WHAT IS THE POSTURE?         -> evidence-backed posture engine
WHAT CAN IT REACH?           -> trust graph / lab
WHAT IS THE BLAST RADIUS?    -> derived reach + sensitive resources
WHAT SHOULD HAPPEN NEXT?     -> detections + policy
WHAT RESPONSE OCCURRED?      -> adaptive response (audited, attestable)
CAN ANYONE VERIFY IT?        -> verifier, passport, attestation
```

## Hard rules

1. **Monitoring never authorizes.** The recorder, network, posture, and
   lab are observational/analytical. None of them can allow an action.
2. **Telemetry never bypasses authorization.** Analysis feeds context;
   the pipeline alone decides.
3. **Simulation never mutates production.** Every scenario runs in an
   isolated throwaway workspace.
4. **The browser never becomes an authorization bypass.** Mutations go
   through the audited control plane; analysis routes are read-only.
5. **Response automation never bypasses policy.** Stages are
   policy-driven, high-impact stages need approval, everything is
   audited and attestable.
6. **Forged identity is never trusted merely for shape.** Signatures,
   status, and fingerprints are all checked; unknown/revoked/rotated
   identities fail.
7. **Unverified evidence is never presented as verified.** Artifacts,
   passports, and attestations each report explicit states.
8. **Fail closed.** Lineage cycles, missing ancestors, revoked
   components, expired tasks, and unverifiable attestations all fail
   closed.

## Identity vs authenticity vs authorization (never conflated)

- **Integrity** -- the hash chain proves content was not altered.
- **Authenticity** -- a valid signature proves the key produced it.
- **Identity** -- a verified identity record binds a key to an agent
  name (subject to issuer trust).
- **Authorization** -- only the SDK pipeline decides what the agent may
  do.
- **Attestation** -- a signed statement about a fact, verifiable but
  never itself a permission.
- **Trust** -- explicit decisions (issuer trust, component trust,
  response approval) recorded with reasons.

## Where v2.0 fits

```text
analysis/history (recorder, network, posture, lab, trust)
        |
        v
   security context (identity, tasks, risk, posture)
        |
        v
existing authoritative authorization (FirewallSDK / North Star)
        |
        v
     final decision
```
