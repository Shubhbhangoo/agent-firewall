# v2.0 Migration Guide (from v1.8 / v1.9)

## What changed

v2.0 is **fully additive**. Nothing in v1.8 or v1.9 was removed,
renamed, or changed:

- v1.8 `.afw` artifacts, the verifier, the recorder, timeline,
  trajectory, graph, containment, replay laboratory, and incident
  packages are unchanged and still work.
- v1.9 network commands (`network`, `detect`, `attack-path`, `respond`),
  the SOC panel, and the integration adapters are unchanged.
- `FirewallSDK.authorize()` remains the decision authority.

## New commands

```bash
# Identity
firewall identity create agent-a --registry identities.json --passphrase pw
firewall identity show --registry identities.json
firewall identity rotate agent-a --registry identities.json
firewall identity revoke agent-a --reason "..." --registry identities.json

# Task-bound authority
firewall task create agent-a --permissions '{"allowed_actions": ["read"]}'
firewall task delegate <task-id> agent-b --permissions '{"allowed_actions": ["read"]}'

# Passport
firewall passport show agent-a --out passport.json
firewall passport verify passport.json --registry identities.json

# Attestation
firewall attestation verify attestation.json --registry identities.json

# Provenance
firewall provenance register tool payments.send --integrity sha256:...
firewall provenance trust trust tool:payments.send:1.0 --reason reviewed
firewall provenance verify tool:payments.send:1.0 file.bin

# Posture / trust / lab
firewall posture state.json --agent agent-a
firewall trust network.json --radius agent-a
firewall lab sweep network.json
firewall lab counterfactual network.json --agent agent-a --added admin.bypass
```

## Migration notes

- **Identity is a new concept.** v1.8/v1.9 artifacts recorded agents by
  name; v2.0 identities bind names to keys. If you want identities for
  existing agents, create them (`identity create`) and attach tasks --
  the artifacts remain valid evidence either way.
- **Tasks are optional.** Existing SDK authorization (capability-based)
  is unchanged. Task-bound authority is an additional scope you can
  adopt per workflow.
- **Passports and attestations are opt-in.** They require an identity
  registry; without one they cannot be issued.
- **State files are new.** Identity (`identities.json`), task
  (`tasks.json`), and provenance (`provenance.json`) registries persist
  to local JSON with atomic replacement. Passphrase-encrypt identity
  keys for durable storage.
- **Browser.** The console gains an identity & supply-chain panel; all
  existing panels remain.
