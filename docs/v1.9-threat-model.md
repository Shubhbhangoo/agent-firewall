# v1.9 Threat Model and Security Review

## What changed versus v1.8

v1.9 adds a cross-agent analysis layer (network graph, correlation,
behavior, attack paths, simulator) and one new write path (graduated
response). Everything new is observational/analytical or routed through
existing enforcement. The authorization pipeline is untouched.

## Trust boundaries

| boundary | who/what | guarantees |
| --- | --- | --- |
| recorder identity | the flight recorder's Ed25519 key | artifacts verify internally; pinning the fingerprint (`--expect-recorder`) is the root of trust |
| artifact ingest | the independent verifier | failed/unverifiable artifacts are refused; their facts never reach the network |
| adapter identity | agent environments | never fabricated; unknown identity degrades to `complete: false` |
| correlation ids | artifact metadata | labels, not proof; bundle verification statuses always reported |
| containment/response | control-plane bearer token | mutations are audited, explained, and routed through SDK revocation/risk |
| scenario simulation | isolated workspaces | never touches live state; outcomes labeled `simulated` |

## Adversarial test coverage

The v1.9 suites (`test_v1_9_adversarial.py`, `test_v1_9_network.py`,
`test_v1_9_integration.py`) cover:

- forged artifacts and forged issuance events refused at ingest
- graph poisoning (injecting an `observed` node post-hoc) rejected
- correlation-id spoofing stays a labeled bundle; verification statuses
  are always reported
- adapter identity never fabricated; unmapped endpoints refuse without
  guessing; unknown environments fail fast
- simulator isolation (live graph unchanged after many runs) and
  contradiction reporting (removing a capability never held)
- approval-denied responses raise rather than silently downgrade
- containment failures surface (fail-closed) rather than leaving an
  agent unrestrained
- reachable-vs-observed status honesty on attack paths
- redacted artifacts correlate but remain `redacted`

## Attack scenarios and mitigations

### 1. Attacker forges an artifact claiming a big capability

The verifier recomputes every hash and checks every signature. A forged
event breaks the chain or the checkpoint signature -> `failed` ->
refused at ingest. Even a recomputed-hash forge breaks the next event's
`prev_hash`.

### 2. Attacker poisons the graph

The graph is built only from verified artifacts. Post-ingest additions
must be explicitly `inferred`/`simulated`; claiming `observed` raises.
Queries carry their basis (`derived`), and path statuses never upgrade
untested hops to `observed`.

### 3. Attacker tampers with correlation

A correlation id is metadata. Bundling two artifacts under one id is
allowed -- the bundle reports both verification statuses and the reason
("shared correlation id"). The network never treats the bundle as proof
of a real relationship.

### 4. Adapter reports malicious tool output

Tool output is data, not authority (v1.5 guarantee). Adapters hold no
signing keys; every protected call is authorized by the real pipeline;
observations are recorded post-hoc and cannot influence a decision.

### 5. Response automation goes rogue

Stages are policy-driven; `quarantine`/`contain` require human approval
unless the policy explicitly auto-approves; every action is audited and
explained; the controller has no signing keys; enforcement is SDK
revocation/risk only -- there is no second authorization system to
subvert.

### 6. Simulator used to bypass authorization

The simulator runs in throwaway workspaces; its outputs are labeled
`simulated`; it cannot modify live revocation, risk, or budgets. A
simulated "allow" is a hypothesis, not a permission.

## Deliberate limitations (never market inference as proof)

- Behavioral detections are `inferred` heuristics with named evidence;
  they are not facts and not AI scoring.
- "Reachable" is not "exploitable". `potentially_dangerous` is an
  analytical label over recorded authority.
- A scenario outcome is `simulated`; a redacted artifact is `redacted`;
  an incomplete recording is `incomplete`. Missing evidence is never
  promoted to trustworthy evidence.
- The console remains a trusted local developer interface (loopback,
  bearer token, audited writes). It is not a hardened multi-tenant
  production service.

## The non-negotiable boundary

Nothing in v1.9 can bypass cryptographic verification, capability
authority, issuer trust, revocation, delegation validation, North Star,
or fail-closed semantics. Analysis feeds *context*; the existing
authorization pipeline alone makes the *decision*. There is no
"AI says safe -> allow" path.
